# N11: 162 mapped variants with shared async-task owners

Historical measurements from the original stack; the rewritten trait-based branch requires fresh measurements for performance claims.

The trait-based rewrite selects task and thread constructors through `Provides<AsyncTaskIntrinsic>` and threads their actual owners through call and callback bindings. It retains the base runtime's cooperative threads, per-thread context slots, task/thread identity validation, host-thread handling and last-thread task retirement. Tests cover recycled indices, context isolation, spawned-thread lifetime and synchronous `task.return` rejection. Thread lookup is isolated from task-map operations to keep the module graph acyclic.

Rewrite validation: 132 Rust tests, 214 runtime behavior tests, both 778-case generated-component suites (776 passing and two existing skips after focused provider reruns), 48 bundler/functional checks, and two Chrome cases. Historical performance numbers below are not measurements of this rewrite.

All 25 async-task variants now use named exports. Separate initializers return
selected task/subtask constructors, actual task Maps and ID/component/stack
arrays, and the two distinct selected raw Global registers. Class statics,
private brands, own prototype methods, `new` and `instanceof` remain per store.
The selected i32 Global constructor contract requires only the mutable value
slot actually used, rather than unused native overloads or prototype methods.
Absent WebAssembly retains the two different inline fallbacks; a present
platform missing Global still throws. Pure lookup does not select either class
or read an unused optional Global.

Lookup, creation and clearing have separate structural contexts. Resources,
core suspending wrappers and waitables share their actual task/register owners
through private state operations, removing five generated callback facades.
Task classes share the resource scope-counter cell and scope-task Map. Private
state operations import no class module, avoiding the component/resource/core
cycle. Default functions call their own static dependencies; a sibling export
override does not implicitly intercept those calls. The lazy future-value
predicate remains until N17, and the waitable event-writer bridge until N12.
Inline remains the production default.

The paired inline fixes retain registered-memory extraction, first-lender
validation, the selected component diagnostic and retirement of synchronous
compatibility tasks. Eight independent generated regressions reproduced the
old failures in both modes and pass after the fixes. Callback bindings preserve
null receivers and metadata order. A separate generated JSPI regression exposed
the slow symmetric-entry wrapper losing its null receiver when context was
bound with void 0. It failed before the fix and passes afterward; the plain
callback still binds void 0, and inline callbacks keep their original identity.

An initial full run also exposed accidentally overwritten observation helpers
in the independent custom resource fixture. Its original tableGet/readTable
instrumentation was restored while retaining the new task-owner wiring. No
assertion or performance threshold was relaxed.

The original native-ratio test failed twice at 1112x and 1063x against its 1000x
limit. Five isolated inline/named pairs found a synchronous cost difference;
profiles localized additional work in task construction. Five counterfactual
pairs using the same named inputs measured 5.49 microseconds with one store
versus 8.93 after warming a second store, a paired ratio of 1.541
[1.492, 1.720]. These diagnostics compare the current implementations, not N10
against N11.

A controlled layout experiment grouped 42 private slots into one per-task private
record. Five fresh balanced before/after pairs measured a synchronous ratio of
0.735 [0.655, 0.772] and async ratio of 0.815 [0.715, 0.830]. All five changed
runs stayed below the unchanged native-ratio bound; two original runs did not.
The final implementation uses that layout. A parsed-token audit verifies all
42 initial values/order and 248 accesses, recovering the original task algorithm
apart from representation and formatting. An emitter audit verifies the isolated
experiment and actual runtime have equivalent emitted syntax tokens. Runtime
regressions retain distinct constructors/statics/methods and rejection of another
store's private brand. This adds an ordinary private record per task; it is not
a memory-saving claim. Raw diagnostic pairs and audits are in
[n11-task-construction.json](n11-task-construction.json).

Final validation passed 109 Rust tests and Clippy; strict runtime/benchmark
types and changed-file lint/format; 184 runtime/package cases, including packed
NodeNext/Bundler consumers, literal standalone contracts, negative fixtures and
exact JS/type exports; 868 full external tests with three existing skips;
279 inline LTS tests; 33 explicit nested inline P3 cases; and four CLI/API cases.
The complete external suite includes all 20 browser provider cases and the
unchanged native-ratio/guest-latency checks. A late structural type refinement
was rebuilt and packed-tested; all 18 runtime JS files remained byte-identical
to the clean full external run. All functional/build processes and task-owned
temporary roots were finished before timing. The previously recorded extended
fixture/toolchain gap remains; unavailable extended coverage is not claimed.
