# N09: 126 mapped variants with selected waitable constructors

Historical measurements from the original stack; the rewritten trait-based branch requires fresh measurements for performance claims.

All eight waitable variants now use named exports, bringing coverage to 126/274.
The context-free waitable initializer and cancellation-code-only set initializer
return fresh per-store constructors. Component state receives the actual selected
waitable constructor; its callback bridge and whole-context capture are removed.
Set creation, wait, poll, drop, removal and join receive their narrow actual
lookup/constructor/trap capabilities. Task lookup remains lazy until N11 and
event writing until N12. Per-call memory metadata remains an operand. All five
bound trampolines insert runtime context before their existing operands and keep
their null receiver. Inline remains the production default.

The separate paired-fix commit preserves four historical corrections in inline
output: reject an undefined set argument; clear the standalone sync waiter in
`finally`; call the task's component-index method in wait diagnostics; and read
poll's metadata index before the task is declared. Four generated regressions
failed before the fixes and passed after a fresh compiler build, in both modes.
All 24 nonempty/non-noise inline bundles change from N08, as do their named
counterparts. All workload core-Wasm digests remain unchanged. Older inline
measurements cannot replace this revision's comparison.

Sixteen fresh serial constructor diagnostics ran after both timing cohorts.
Counts match exactly within all eight bundler/workload pairs at import,
instantiation and after verified answers. Import-time counts are zero. Adder and
resource initialize seven Maps and one symbol; sharing initializes fourteen Maps
and two symbols. Numbers initializes eleven Maps, two symbols, one DataView,
ArrayBuffer, Uint8Array, Uint16Array and TextEncoder. Other traced constructors
are zero. The worker, source hash, selected-owner graph and phase counts are in
[constructor traces](n09-constructor-traces.json).

These traces rule out extra instances of the listed native constructors in the
tested paths. They exclude ordinary objects/array literals, closures, class
identities/lexical environments and Promise/native internals, so they do not
prove equal allocation or explain the timing penalty. Named context views and
constructor-initializer calls remain source-level candidates. N14 must factor
these costs before making an architectural speed or memory claim.
